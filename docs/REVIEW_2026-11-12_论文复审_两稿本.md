### 2.2 P0-1：把"会话数"当"事件数"报

这是最容易致命、也最容易修的一条，但它牵连全部数字。

`p153` 的 4 行 test 记录是：

```
relaxed_high_drift_capacity_region   served=64   -> viscontract_r025_hot4_offload
strict_high_drift_latency_region     served=32   -> uniform_kivi2
relaxed_moderate_capacity_region     served=64   -> viscontract_r025_hot4_offload
stable_capacity_region               served=64   -> viscontract_r025_hot4_offload
                                       sum = 224
```

论文把这个 `sum = 224` 写成 "served 224 test events"。实际发生的是：**4 个事件分类，每个分类按 32/64 并发服务，共 224 个会话**。同理 `p152` 的 352、`p157` 的 320 都是会话数。

后果不是"数字虚高"这么轻，而是**统计单元被替换了**。`p153` 报的五折 bootstrap CI [0,0] 是对"会话"重采样的；但会话在同一事件分类内质量完全相同，重采样不产生任何方差。所以那个"零方差"是在告诉读者：这 4 个格被完美复现了。它不是"留出验证成功"的证据，它是"样本量 = 4"的证据。

### 2.3 P0-2：留出准入是构造性的，不是经验性的

把 `p153` 的 protocol 字段直接读出来：

- `calibration_event_ids`：4 个，名字分别是 `stable_small_static_ok`、`moderate_small_static_ok`、`strict_drift_kivi_region`、`relaxed_drift_capacity_region`
- `test_event_ids`：4 个，`relaxed_high_drift_capacity_region`、`strict_high_drift_latency_region`、`relaxed_moderate_capacity_region`、`stable_capacity_region`

这 8 个名字本身就是**"这个事件该选哪个策略"的答案标签**（`strict_drift_kivi_region` 直接写着 kivi）。而候选策略只有 3 个。在这种情况下，"admission 恰好等于 oracle"几乎是定义上成立的：只要规则在 4 个 calib 格上学到"高漂移高容量 → 用 viscontract"，它在 4 个 test 格上就会做对，因为 test 格的名字就在同一套分类体系里。

同样的结构出现在 `p157`：8 个事件、4 个候选策略，admission 与 offline_oracle 的 `regret_vs_oracle` 都是 0.0。**在所有报告的实验里，admission 都精确等于 oracle。** 一个方法在 4 格、8 格、20 格上都不差一分，这不是性能好，这是这套评估没有区分能力。

这是 A 稿的真正死因：**它不是被审稿人质疑"结果不够好"，而是被质疑"这个实验不可能失败"**。一个不可能失败的实验，无论跑多少次都不是证据。

### 2.4 P0-3：事件级质量根本不存在，所以"per-event admission"名不副实

`p145_joined_quality_system_rows.csv` 共 400 行，看起来样本量充足。按 (policy, drift_rate) 分组：

- 策略 4 个 × 漂移档 5 档 = **20 个格**
- 每格 20 行
- **同一格内 `quality_score` 完全唯一（是常数）**

例如 `uniform_kivi2` 在 drift=0 的 20 行里，`quality_score` 全为 `0.8458`，差别只有 `served_quality_sessions`（6.77 / 13.53 / 27.07 / 54.13 / 81.20，即 1×/2×/4×/8×/12× 的会话倍数）。

也就是说：**质量的自由度是 20，不是 400。而且质量不随事件变化，只随 (策略, 漂移档) 变化。**

这直接推翻了三处表述：

1. "per-event admission"——事件级唯一的变量是容量和 SLO 类别，质量是查表。
2. "quality gate uses calibration-split or evidence-tier information"——质量门限是在 20 个常数上做的阈值判断。
3. 所有以会话为单位算的置信区间都严重高估了有效样本量。真实自由度：质量轴 ≈ 20，SLO/容量轴 ≈ 数个，模型轴 = 3。

顺带一个假精度问题：`p157` 里 `quality_score` 被写成 `0.84`（两位小数），于是 raw utility = 32 × 0.84 = 26.88。论文报 `261.76`、`234.88`、`317.544` 这些四位有效数字，精度来自 32 会话乘 0.84 的乘法，不是来自测量。审稿人只要复算一次就会问：你的质量分是几位有效数字？

### 2.6 新颖性：审稿人会怎么问

A 稿自己在 §2 末尾承认了问题所在，却把它当成优势写：

> "The resulting problem is also connected to a long multimedia-systems tradition: admission control and QoE-aware adaptation … VisContract maps that idea from network bandwidth, disk service, and encoded representations to visual-evidence residency inside VLM serving."

一个 MM 审稿人读到这句，第一个问题是：**"这不就是把多媒体 admission control 搬到 KV cache 上吗？搬过去之后，控制理论有变化吗？"** 论文的回答是"被控对象从码率变成视觉状态"——这是对象的替换，不是方法的推进。

第二个问题：**四门禁（Q/C/L/W）为什么是这四个、为什么是与关系、门限怎么定？** 论文的处理是逐事件用冻结表查；没有刻画门禁之间的耦合（例如 wake 争用会同时打穿 L 和 W），也没有给出任何可迁移的判定条件。`G_Q·G_C·G_L·G_W = 1` 这个式子本身不构成贡献——它是一句同义反复。

第三个问题，也是最致命的：**既然你的 admission 在所有实验里都等于 oracle，那这个"控制层"到底决定了什么？** 如果答案是"决定在 4 个已知事件分类里选 3 个策略之一"，那它就是一张查表。

**模拟拒稿理由（我作为审稿人会写的三条）：**

1. *The evaluation has no power to falsify the proposed abstraction: admission matches the offline oracle in every reported experiment, over 4–20 decision cells, with per-cell constant quality. Zero regret therefore reflects the construction of the replay table, not generalization.*
2. *The unit of analysis is inconsistent: "events" are session counts; statistical claims are computed over replicated cells.*
3. *No strong baseline is faithfully reproduced; the strongest comparator is a re-parameterized version of the authors' own policy.*

### 3.2 P0-4：DRG 在数学上不可伪证

这是 B 稿最根本的问题，必须说清楚。

契约定义（§5.3）：turn 1 用 selector 选 $S_1$，其余 $P\setminus S_1$ 进 dormant；后续 turn 若 gate 触发，则把 dormant 全部重建并重新暴露。

于是对每个 turn $t$：

$$E_t^{\mathrm{Lift}}(p) \;\supseteq\; E_t^{\mathrm{Static}}(p), \qquad \text{且 gate 不触发时取等号}$$

即 **Lift 的暴露集在每个 turn 都是 Static 的超集**。而

$$\mathrm{DRG}(f) = \mathrm{Score}(\mathrm{Lift}(f,g,p)) - \mathrm{Score}(\mathrm{Static}(f))$$

在"更多视觉证据不会让答案更差"这个前提下，DRG **恒 ≥ 0**。论文报的所有 +4.01 / +4.43 / +4.86 / +7.87，本质上度量的是：

$$\text{DRG} \;\approx\; \underbrace{(\text{Full} - \text{Static})}_{\text{选择造成的可恢复损失}} \times \underbrace{\text{wake rate}}_{\text{gate 触发频率}} \times \underbrace{\eta}_{\text{额外证据真正有用的比例}}$$

它度量的是**"多给上下文的价值 × 你多给的频率"**，不是**"契约这个设计选择的价值"**。

这一点在 B 稿的写法里被系统性地混淆了。原文 §1：

> "Because the selector is held fixed, DRG isolates the effect of recoverability from the effect of selector quality."

前半句对（selector 确实固定了），后半句错。固定 selector 只排除了"换了个更强的 selector"这一个混淆项；它**没有排除"暴露得更多"这个混淆项**，而后者才是 DRG 的主要来源。

**能证伪这个设计的实验只有一个**：在**匹配 wake rate** 的条件下，把真 gate 换成
(a) 随机触发、(b) 周期触发、(c) oracle 触发，看 DRG 是否显著高于 (a)(b)。

- 如果 DRG(真 gate) ≈ DRG(随机)，那么"契约"= "按固定概率多给上下文"，gate 无信息，方法退化为"提高保留率"。
- 只有 DRG(真 gate) 显著高于 DRG(随机)，且接近 DRG(oracle)，"gate 有信息"才成立。

B 稿把这个对照写进了 §8.4 的 TODO（"matched-trigger random/periodic/oracle controls"），但**没有跑**。这不是遗漏，这是主结论缺了唯一的关键对照。

### 3.3 P0-5：这个 gate 已经被作者自己的预注册实验判死

`docs/p163_formula_novelty_reassessment.md` 记录的 P164 是新鲜、零重叠、预注册的实验，结论写得很直白：

| 指标 | GQA | ConvBench |
|---|---|---|
| gate AUC | 0.585 | 0.623 |
| wake rate | 44.6% | 68.0% |
| recall | 54.4% | 86.4% |
| DRG | +4.00 pp [1.00, 7.14] | +0.46 pp [-0.25, 1.36] |
| **净效用**（含预注册 wake 成本） | **−0.00034** | **−0.02325** |
| 校准 | 预测 45.1% / 实际 8.1% | 预测 47.7% / 实际 14.7% |

判定：`FAIL_P0_QUERY_GATE`。

三个要点：

1. **AUC 0.585 意味着 gate 几乎不比抛硬币好。** 而 B 稿的核心卖点是"gate 决定何时暴露"。
2. **净效用为负**，且是相对于"永不唤醒 = 0"为负。也就是说：**这套 gate 比什么都不做更差**，因为它付了 wake 成本却没换来对应收益。
3. 校准极差（预测 45%，实际 8%），说明 `m_t(p)` 这个 page-need score 的尺度本身没有意义。

B 稿 §5.5 还在说 "It is conservative and fail closed: it prefers to re-expose when the query changes"——"保守"在这里是委婉说法，实际含义是"几乎总触发"，也就是 §3.2 里 DRG 的主要来源（wake rate 高）。**论文把 gate 失效包装成了 gate 保守。**

这是最需要在复审里点明的一条：**B 稿的主结论与作者自己后来的预注册结果是直接冲突的，而后者证据等级更高。**

### 3.4 P0-6：精度准入是两套判据混用

A 稿表 3 / B 稿 §7 的核心是"4-bit 被拒、8-bit 被接受，所以边界是被测出来的，不是空检查"。回查证据：

| 档位 | 样本数 | 判决所依据的检查 | 该检查结果 | 同一文件里的等价性检查 |
|---|---|---|---|---|
| 4-bit | **n=1** | 生成是否"invalid" | invalid（但 `failure_reasons` 含 `trace_length_mismatch`） | `compact_semantic_oracle.pass = false`，`max_abs_logit_diff = 30.125` |
| 8-bit | n=8 | wake oracle 对账 | 8/8 exact，logit diff 0.0 | `compact_semantic_oracle.pass = false`，`max_abs_logit_diff = 51.28` |

三个问题：

1. **两档用的不是同一个判据。** 4-bit 被"生成无效"拒，8-bit 被"对账精确"收。把两个不同测试的结果并排放进一张"边界表"，不能证明边界存在，只能证明这两个配置在不同的检查上失败/通过。
2. **两档的等价性 oracle 都没通过**（30.1 与 51.3 的 logit 差）。8-bit 那个 "8/8 exact" 检查的是 chunking/索引/就地写回的对账，**不是** mask-vs-compact 的注意力等价性。A 稿只报了前者，没报后者；B 稿 §4.5 承认这是 "open diagnostic"，但 A 稿完全没提。**同一批数据在两稿里被报告成了两个不同的结论强度。**
3. **n=1 且失败含长度不一致**，这更像是 4-bit 路径的实现 bug（解码提前终止），而不是"4-bit 表示不可用"的科学结论。

### 3.5 经济学论证自相矛盾

B 稿 §7 的生命周期表（8-bit 准入配置）：

| 阶段 | Cache ratio |
|---|---|
| full prefill | 1.000 |
| hibernate | 0.689 |
| re-expose | **1.403** |
| wake decode | **1.433** |
| steady | 0.719 |

wake 瞬间占用 **1.4× Full**。这意味着：

- 论文的容量卖点只在 hibernate 稳态成立（省 31%）。
- 一旦 gate 触发（P164 实测 44.6% 的 turn），瞬时占用超过 Full。**在容量受限的服务里，这正是 `G_C` 会失败的时刻。**一个 fail-closed 的准入层，不能准入一个在运行中必然越界的策略。
- 稳态 0.719 + 45% 的 turn 要花 33.5 ms 唤醒，与"直接把保留率从 0.25 提到 0.75"相比，**没有明显的资源前沿优势**——后者不需要 gate、不需要 wake 路径、不需要 dormant 编码。

**这就是审稿人一定会问的那个问题：既然 Lift 在 wake turn 上≈Full，wake rate 又接近一半，为什么不干脆用更高的静态保留率？** 论文没有给出"同等实际字节下的对比"（B 稿 §5.4 只说报 logical resident ratio，明确不报端到端内存）。这条不补，方法的必要性论证是空的。

## 4. 两稿共有的根问题

一句话：**把"多看了 token"当成了"契约的价值"。**

这个错误在两稿里以不同面貌出现：

| 表现形式 | 出现位置 |
|---|---|
| DRG = Lift − Static，而 Lift ⊇ Static | B 稿 §5.7 |
| "full admission served all 352 events, utility 317.544"——admission 等于 oracle | A 稿 §5.1 |
| "removing each axis causes a distinct failure mode"——实际是查表换行 | A 稿 §5.1 |
| "4-bit rejected, 8-bit qualified"——两套判据 | A/B 稿 |

共同的修复方向只有一个：**所有"收益"必须在同一资源账本下与"最笨的基线"比较**。

具体到这两篇，最笨的基线分别是：

- B 稿：**同等实际字节（含 dormant 存储 + wake 峰值摊销）下的静态保留率**。
- A 稿：**同等违例数下的固定策略**，而不是"同等策略下的违例数"。

这两条不补，任何包装都过不了好期刊的审稿。

## 5. 可以保留的资产（这是这轮复审最重要的正面结论）

不要全盘否定。这个项目里有四样东西是真的，而且是有价值的。

### 资产 1：操作语义四分类 + key-zero 的 softmax 吸引子伪影

`key-zero / value-zero / faithful mask / physical delete` 四种"删除"操作不等价，其中 key-zero 会产生 query 无关的常数分数，经 softmax 后形成吸引子，**系统性夸大删除的伤害**。

这是一个真实的、可复现的、对社区有用的**方法学纠正**。它的价值不在"我们发现了"，而在"很多人用错了，而且错的方向是夸大自己的失败"。这类负结果/纠正性结果，在好的会议/期刊上是有位置的（作为 measurement / position paper 的一节，或独立短文）。

**但必须重做**：现有版本是用 KL/probe 报告的，不是用配对因果协议报告的。要用 P173/P174 那套 same-state 协议重测。

### 资产 2：selector-fixed 配对设计（框架，不是数值）

"固定 selector 比较 Lift 与 Static"这个配对思路是对的、干净的、可复用的。缺的只有一条：**matched-wake-rate 对照**。补上这条，DRG 就从"不可伪证的单调量"变成一个真正的因果估计量。

### 资产 3：模型集成的 packed-cache 审计清单

`p108/p110` 那套审计（live cache 就地替换、无 FP16 残留、allocator 对账误差 0 字节、post-wake scratch 泄漏 0、位置/顺序 oracle、chunked wake vs 单体反量化参考）是**扎实的工程可信度资产**。这部分写进论文会加分，因为它证明"我们真的动过模型的 cache"，而不是在 replay 表上算数。

前提是把 `compact_semantic_oracle` 的 30~51 logit 差查清楚。现在还挂着一个未解释的三位数 logit 偏差，这本身是个可发表的发现（"eager attention 下 mask 与 compaction 不等价"），但必须先定位。

### 资产 4：P164 的负结果

gate 失败（AUC 0.585、校准 45% vs 8%、净效用为负）是一个**高质量的负结果**。它比很多正结果更有信息量：它说明"用词面查询变化预测视觉证据需求"这条路不通，而且给出了量化的失败幅度。

这个结果可以直接撑起一篇短文的一节，或者作为新论文的 motivation（"我们试过最便宜的信号，它不行，所以我们转向 X"）。**不要把它藏起来。**

## 6. 对 TrajKV / PLAN_v2 的直接影响

你在 `docs/PLAN_v2_轨迹感知精度分配.md` 里的两个假设（H-A 敏感性漂移、H-B 历史介导）方向是对的，而且比 A/B 两稿的问题更根本。但有四处需要按本轮复审修订：

### 6.1 必须追加的判据：matched-trigger 对照（建议写入 ERRATA 第 6 条）

PLAN_v2 里凡是出现"条件策略优于固定策略"的地方，都必须同时报"同触发率下的随机/周期触发"基线。理由见 §3.2——这是 B 稿翻车的直接原因，也是最容易在新项目里重犯的错。

建议的 ERRATA 文本：

> **第 6 条：可恢复收益必须在同触发率下对照。** 任何形如 `Score(条件策略) − Score(固定策略)` 的指标，在条件策略的暴露集是固定策略超集时，其符号由单调性假设决定，不能作为方法有效性的证据。判据：必须同时报告 (a) 同触发率随机触发、(b) 同触发率周期触发、(c) oracle 触发的配对差值；只有真信号显著高于 (a)(b) 时才可归因于信号本身。P164 的 gate（AUC 0.585，净效用 −0.00034）是这条判据的反例。

### 6.2 P0-B 的优先级要提前，而且它的结论会改变整个叙事

`p145` 的经历已经说明：**如果 KIVI2 距 FP16 只有 0.8pp，那么"精度压缩导致质量退化 → 需要精度恢复"这个前提在 GQA 上只有 0.8pp 的空间。** 而选择轴（static TGV r=0.75 vs Full）的损失是 11.6pp。

两者差一个数量级。这意味着：

- **可恢复的损失主要来自"选错了 token"，不是"存错了精度"。** A/B 两稿之所以一直在"恢复"上打转，是因为它们的损失源其实是选择，不是精度。
- 你现在的 PLAN_v2 把重心放在精度分配上。如果 P0-B 复现出 0.8pp 这个 ceiling，那 TrajKV 的主战场必须换——不是"精度该怎么分配"，而是"为什么选择造成的损失比精度损失大一个数量级，以及历史状态在其中起什么作用"。

**建议：P0-B 从"审计项"提升为"Go/No-Go 关卡"。** 它决定 PLAN_v2 是否还成立。

### 6.3 H-B（历史介导）应该升级为主假设

P213 那条线索（改前一轮隐状态能影响后一轮的图像事实归属）是**唯一一个现有强基线方法没有覆盖的机制**。而 A/B 两稿的失败恰恰说明：在"哪个 token 该多给精度"这个平面上，已经被 KVTuner/AATC/MixKVQ/TriAxialKV 挤满了。

历史介导如果成立，问题就从"分配"变成"传播"，这是一个不同的科学问题，也才有辨识度。

### 6.4 验收线：把"超过 +2pp"换成"gap closure + 资源前沿"

现有 +2pp 的验收线在 GQA grouped 上等于要求超过 FP16（因为 KIVI2 只差 0.8pp）。建议改为：

- **Gap closure**：$\mathrm{GC} = \dfrac{\text{方法} - \text{最强低比特基线}}{\text{FP16} - \text{最强低比特基线}}$，要求 $\mathrm{GC} \ge 30\%$ 且 gap ≥ 5pp（gap 太小则 GC 无意义）。
- **资源前沿**：在同等实际字节（含 dormant 存储、wake 峰值摊销、编码开销）下比较，而不是在 logical ratio 下比较。

这两条与 ERRATA 第 4 条（gap closure）一致，但需要补上"实际字节"的口径定义——A 稿 §5.4 明确说"we do not present either as an end-to-end production memory result"，这个免责声明在审稿里等于承认资源账本不闭合。
