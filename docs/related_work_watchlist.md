## 2. 每篇必须抽取的六个字段

不要只记"它做了什么"。逐篇填这张表，填不满就是没读懂：

| 字段 | 为什么重要 |
|---|---|
| **比特分配的依据** | 静态标定 / 当前 query / 结构标签 / 实测失真曲线 —— 决定我们和它的差别是不是只在"依据"上 |
| **是否跨轮** | 是"单次建缓存后复用"，还是"每轮重建"；有没有测 t≥2 |
| **目标函数** | 重构 MSE / 注意力输出 MSE / logit KL / 下游准确率；有没有尾部项 |
| **字节口径** | 分母是什么、含不含元数据、等不等字节比较 |
| **是否开源 + 能否在 3090 跑** | 决定它能进 L4/L5 还是只能写进 related work |
| **它明确没做什么** | 原作者自己写的 limitation，通常就是我们最好的差异点 |

## 3. 我们的差异（当前版本，待实验确认后才可写）

> 这句话现在只是**待检验的假设**，不是结论。

- 上述工作的优化目标是**某个分布上的期望失真**：标定集、当前 query、或结构标签。
- 我们问的是：**这个期望在轨迹上是不是一个坏目标**——即用 t=1 选出的配置，在 t≥2 是否系统性失效（H-A），以及误差是否经文本状态传播（H-B）。
- 如果 H-A/H-B 成立，"轨迹鲁棒"与"历史敏感"就是它们没有的能力；如果不成立，我们就只是又一个混合精度配置，**没有资格投 CCF-A**。

**禁止写法**："现有方法都没有考虑多轮"——TriAxialKV 已涉及多轮结构。正确写法是"它们用结构标签刻画轮次，我们用实测状态传播刻画"。
