## 0. 一页速览

**一句话**：这个项目在两天里从"什么时候多读一次 KV"转向"低比特压缩到底破坏了什么、以及用多小的额外代价能修回来"，并完成了从机制诊断到独立确认的完整闭环——结论是**表示收益已经确认、质量目标尚未达到、读取收益已确认但延迟收益不存在**。

**六条已确认的结论**

1. **触发器路线判死**：所有"何时精化 / 何时升级"的在线触发方法都没有在独立确认上稳定胜过简单控制（最强的一条在探索集 +2.43pp，确认集只剩 +0.137pp、区间跨 0）。
2. **一比特 K 的失效大部分可修，但不是单一原因**：同字节、同格式下，只换重建电平就能把 K 的 ANLS 从 0 拉到 56.76、两质心到 62.98（20 题探针）；在新 64 图确认上，1-bit Lloyd 30.48 → 去中心 RMS 修复 60.15。
3. **方向比范数更重要，但范数也值钱**：四臂 oracle（V 固定 FP16、K 全部材料化为 FP16）在新 64 图上是 51.03 / 66.49 / 85.05 / 87.95；真实方向比真实范数高 18.56pp（区间 [13.86,23.74]），范数单独也值 15.46pp。**不能写成"长度无关"，也不能把差值算成"方向解释百分之多少"。**
4. **校准必须匹配"问题状态是怎么形成的"**：同样 224 个量化因子、同样参数量，用压缩前缀重新形成问题状态再校准，比在原生历史条件下校准高 6.73pp（[3.33,10.46]），并在 TextVQA 外部复测中复制（+7.42pp）。
5. **存储-质量有真实交易**：约 1.695 bit/scalar 拿到 87.87 ANLS（Base2 88.76、Native4 91.97），即**视觉存储省 24.75%、质量低 0.89pp**；更激进的 1.579 bit 拿到 86.60（省 29.90%、低 2.16pp）。
6. **读取轴省字节成立、省时间不成立**：同存储下 risk 策略额外逻辑读少 78.56%、质量只差 0.59pp；但端到端计时里 risk 反而比全精化慢 12.4%，减少逻辑字节没有变成加速。

## 1. 项目在做什么（给没读过任何材料的人）

**任务**：在多模态大模型里，把视觉 KV cache 压到极低比特，同时尽量不损失"看图答题"的质量；并研究"压缩图像前缀"如何影响后续对话状态。

**模型与硬件**：完整 InternVL3-8B-hf（Qwen2 语言骨干，28 层、4 个 KV head、每 head 128 维），统一 FP16，自有双 RTX3090 24GB 做真实 CUDA 推理；Windows 本机只做调度、统计、绘图。**没有 CPU 替代模型，也没有调用付费 API。**

**四个必须说明的度量口径**（否则数字会被误读）：

| 口径 | 定义 | 为什么重要 |
|---|---|---|
| **bit/scalar** | 视觉 KV 每元素平均比特，含 payload + scale/min + 位置 + 增益 + decoder 必需常量；encoder 侧校准常量另列并保守计入 | 这不是"整模型显存压缩率"，也不是峰值显存 |
| **packed** | 候选方法读写的是真实打包码字，不是材料化原型 | 材料化原型（含 oracle）单列，不进部署价格表 |
| **自由生成** | 模型自行生成答案，不喂标准答案，同一图最多 6 问 | 与 teacher-forcing 的分布代理分开报告 |
| **ANLS vs soft accuracy** | DocVQA 用 ANLS；TextVQA 用官方 10 标注 soft accuracy | 两个指标**不混称、不互换** |

**工作负载**（论文里必须写清，否则对比无效）：先形成可复用的图像前缀并压缩，再接收问题；也就是说问题状态必须**通过压缩前缀重新形成**。程序先做原生 image+question prefill 但丢弃问题状态，再用压缩前缀重放完整问题——**第一答案 logit 不与 FP16 共享**。这条是后面"状态匹配校准"的全部由来。

## 2. 六个阶段的推进（按时间）

### 阶段 A（11-12 上半）：触发器与读调度——负结果，但把问题问对了

**做了什么**：并行试了事实载体 K/V、写入 margin、局部重算、当前/未来收益表、双读探针、周期精化；建了完整 GPU 执行器、base+residual 真实 packed 读取、真实调用资源账、同 token 分支仪器。

**规模与结果**

| 工作 | 规模 | 结果 |
|---|---|---|
| CLEVR 主评测 | 64 图 ×10 问 ×19 配置，12160 回答 | 新触发器没有稳定胜过简单控制 |
| 独立阈值复测 | 32 图 ×10 问 ×12 配置，3840 回答 | 升级比例可标定，质量优势未建立 |
| 四预算扫描 | 16 图，2560 回答 | cohort 嵌套，不增加独立图像数 |
| Doc 探索 → 确认 | 探索 16 图；确认 64 图 294 问 ×12 配置 | 未来表探索 +2.43pp，确认 +0.137pp、区间跨 0 |
| 机制/外部 | 同 token 四臂、载体手术、GQA/ConvBench/描述桥接 | 数值状态路径存在，但 margin 不是通用损害判据 |

**学到的**：不是"多读一次"的时机问题，而是"压缩表示丢了什么"的表示问题。这条转向是本项目最重要的一次选择。

### 阶段 B（11-12 下半 ~ 11-13）：极低比特表示——先分开电平、分组、轴、范数与方向

**做了什么**：把"1 bit 到底坏了什么"拆成可独立控制的因素，做了一层阶梯 + 一个四臂 oracle。

**20 题 9 图探针（单侧压缩，另一侧 FP16）**——`results/a2_analysis_value/summary.json`（已复核 14 个变体）

| K 的编码（全部 1.25 bit/scalar） | ANLS |
|---|---:|
| min/max（半极差） | **0.00** |
| 零中心 sign（±E\|x\|） | 28.00 |
| 中心化 MAD（μ±E\|x−μ\|） | 56.76 |
| 两质心 Lloyd（组内拟合） | 62.98 |
| K2 min/max（2 bit） | 94.29 |
| FP16 | 93.04 |

**学到**：同字节、同分组、同格式，只换重建常数就横跨 63pp——编码常数是真实变量，不是细节。

**范数 × 方向四臂（新 64 图确认，286 问）**——`results/frozen_confirm64_analysis/table.csv`（已复核）

| K 的干预（V 固定 FP16，K 全部材料化） | ANLS | 95% 区间 |
|---|---:|---|
| 量化范数 + 量化方向（A00） | 51.03 | [44.51, 57.55] |
| 真实范数 + 量化方向（A10） | 66.49 | [60.12, 72.66] |
| 量化范数 + 真实方向（A01） | 85.05 | [80.27, 89.34] |
| 真实范数 + 真实方向（A11，即 Full cap8） | 87.95 | [83.75, 91.69] |

**开发阶段同一实验在 100 图上（V 严格 FP16、四臂都持 FP16 重构）**——`results/radial_oracle100_analysis`

| 编码 | A00 量化范数+量化方向 | A10 真范数 | A01 真方向 | A11 Full |
|---|---:|---:|---:|---:|
| MAD 电平 | 49.48 | 67.30 | 86.31 | 86.67 |
| Lloyd 两质心 | 54.93 | 66.23 | 88.69 | 86.67 |

**学到**（这条改写了论文主线）：

- 方向臂比范数臂高 **18.56pp**（64 图确认，区间 [13.86, 23.74]，六主比较 Holm 校正后仍显著）→ **方向是主因**。
- 但范数单独也值 **15.46pp**（100 图上是 11–18pp）→ 不能写"长度无关"，也不能说"范数可忽略"。
- 四臂有交互 → **不能用差值算"方向解释百分之多少"**；也不能把 100 图/64 图/20 题三个口径混着比（三处数字不同）。
- **机制解释**：对真实 K 的重构误差做正交分解，**角度项约 94%、径向项约 6%**（`docs/EXECUTION_CHECKPOINT_2026-11-14.md`）；同时 MAD/Lloyd 的**组内范数相关仍有 0.69/0.73**——范数不是被"压成常数"，而是动态范围被压扁。这两条合起来解释了"方向臂高得多、范数臂也涨"的结果。
- 几何侧写（`results/geometry20_analysis`，仅局部视觉 attention，不是答案准确率）：MAD 的 key 余弦 0.936、视觉 top-1 一致率 14.8%、score 相关 0.879；K2 余弦 0.962、top-1 一致率 37.4%。
- 结论句：**逐元素 MSE、角度、SNR 各自只描述部分条件；`SNR>1` 或 `SNR>5` 都不是这里的普适门槛。**

### 阶段 C（11-13）：校准与"状态形成"——本轮最反直觉的发现

**做了什么**：只优化 **224 个量化因子**（模型权重全冻结、不用标准答案），目标是 FP16 第一答案的**词表分布**；因子在编码时**折叠进已有的 FP16 scale/min**，decoder 不新增张量。两种校准的唯一区别是：问题状态是通过**原生高精度前缀**形成，还是通过**压缩前缀重新形成**。

**新 64 图结果（286 问）**——同表 `results/frozen_confirm64_analysis/table.csv`

| 方法 | bit/scalar | ANLS |
|---|---:|---:|
| 原生 K2/V1（min/max） | 1.752 | 65.96 |
| K2 + per-channel Lloyd V1 | 1.752 | 78.98 |
| **原生历史条件下校准** | 1.752 | **74.40** |
| **压缩前缀重新形成状态后校准（冻结主候选）** | 1.752 | **81.13** |

**学到**：状态匹配版比原生历史版高 **6.73pp**（[3.33, 10.46]），在 TextVQA 外部复测中复制（**+7.42pp**，[2.73, 12.58]）。含义是：**同一个问题 token，在高精度图像前缀下和在低比特图像前缀下形成的隐状态不一样**——"压缩表示的影响"不止于当前层的加权输出，还会通过后续文本状态继续传导。

**三种"问题状态形成方式"的直接对照（开发 100 图，同 codec 同图）**——`results/state_formation100_analysis`

| 编码 | 完整问题经压缩前缀形成 | 保留原生问题历史、只重读末 token | 共享原生首 logit | Full |
|---|---:|---:|---:|---:|
| MAD 联合 | 33.53 | 62.86 | 65.34 | 86.67 |
| 原生 K2/V1 | 65.53 | 77.94 | 82.54 | 86.67 |

**读法**：**同一套压缩表示，只因为"问题状态在哪儿形成"，ANLS 就能差 17–32pp**。这是本项目最容易被第三方忽略、但对结论影响最大的一条口径——也是为什么论文里必须写清"先压前缀、再收问题"这个工作负载（`state_formation100_analysis` 里三种协议都被明确承认是合法工作负载，主任务是第一种）。

### 阶段 E（11-14）：码本与 V 修正——更便宜的部分开始显现

**做了什么**：在真实 packed 前向、直通梯度下，用完整冻结 8B 模型校准**逐层/逐 KV-head 的 K 重建表**，以及**可选的 V 增益/中心**；做 K-only / V-only / 联合 / 全局 四臂，避免把联合效果全算给 K。4 个 400 步拟合后，1152 次开发会话、704 条连续指标、3136 条几何仪器记录。

**另 128 份新源文档、501 问、18 配置、2304 次会话、9018 条答案**——`results/book_confirm_doc128_analysis/table.csv`（已复核）

| 方法 | ANLS | bit/scalar |
|---|---:|---:|
| Native4 | 91.68 | 4.252 |
| Base2 | 87.74 | 2.252 |
| 冻结 warm 联合主候选 | 87.47 | 1.731 |
| **warm 联合拟合的 V-only 应用** | **87.73** | **1.695** |
| 未校准 global 方向码 | 86.01 | 1.695 |

**学到**：**只学 K 表几乎没有独立收益；V 修正才是有效的那一半**（V-only 比 global 高 1.72pp，[0.54, 3.13]，Holm p=0.0382）。机制上，V-only 与 global 的 K 完全相同、固定 query 下 K-score 也相同，但**后续层的 query 变了**——说明 V 能通过隐藏状态影响后续读取，不只是当层加权输出。**这仍然不等于"跨轮误差必然累积"。**

### 阶段 F（11-14 收尾）：功能参数化校准——1.695 与 1.579 两个资源点

**做了什么**：把校准从"逐层表"缩到**少量功能参数**（K 中心化/整体增益、V 增益/中心），12 个 400 步无标签拟合比较两种分组（每 128 token vs 整图）；冻结主方案后再在**另一批 128 份新源文档、485 问**上做一次确认（8 配置、1024 会话、3880 答案），输入与参数在新数据之前固定。

结果见第 0 节表。**其中最强的一条统计结论**：整图分组上的功能校准把 83.02 → 86.60，**+3.57pp**，[1.51, 5.71]，主要 Holm **p=0.00372**。

**学到（直接推翻了一条此前的计划假设）**：**"元数据可以先无损省掉"不成立**——同样未校准，g128 是 85.75，整图分组只有 83.02，**元数据压缩本身带 −2.73pp 的质量代价**；后续校准追回了大部分，但"先省后修"不是免费的。

## 3. 用了哪些方法（技术清单）

| 方法 | 具体做法 | 作用 |
|---|---|---|
| 真实 packed 执行器 | 压缩后立刻 `del` 原张量，解码走打包码字；文本 KV 全 FP16 | 保证 bit 数字与部署一致 |
| 四臂 oracle（范数×方向） | 只改解码重构、不动内核，把 K 材料化成 FP16 | 把"坏了什么"拆成可检验的因果臂 |
| 教科阶梯 | 同字节只换电平（min/max→sign→MAD→Lloyd） | 把"编码常数"变成可观测量 |
| 分组/轴正交对照 | per-channel vs per-token、g128 vs 整图 | 分开"轴""分组""重建目标"三件事 |
| 功能校准（折叠式） | 只学 224 个量化因子，折进既有 F16 scale/min；decoder 不新增张量 | 零运行时开销的修复 |
| 安装器码本 / 旋转 | 逐层 K 重建表、FWHT、向量码 | 探索"方向分辨率"的便宜实现 |
| 读取策略矩阵 | 不精化 / 全精化 / 周期 / 随机 / mass / risk / 仅 prefill | 把"读轴"从直觉变成剂量实验 |
| 独立审计 | owner 字节公式、来源比对、hash 清单、逐配置运行参数核对 | 让结论可被第三方复核 |
| 固定输出计时 | 每个问题强制同一组 8 个 FP16 输出 token | 让"延迟"在输出长度可比的条件下比较 |
| 冻结契约 | 方法、参数、主比较在结果产生前写死（`audit/a2/frozen_confirmation_v2_mechanism.json` 等） | 防止事后挑赢家 |

**读法**：从 2.25 bit 到 1.70 bit 只丢约 0.9pp，但**离"距强参考 0.5pp"还差一个数量级**（4.1pp）。方向码在 256 文档上对它自己的同价对照（Lloyd）有稳定 +3.35pp，**但这是"同价对照"，不是"强参考"**。

### 4.2 读取轴（同存储、不同读法）

| 策略 | 额外逻辑读节省 | 相对全精化 ANLS |
|---|---:|---:|
| risk 代理 | **78.56%** | **−0.59pp** |
| mass | 78.48% | −0.88pp |

| 周期精化 | 75.03% | −2.00pp |
| 随机 | 78.73% | −2.36pp |
| 不精化 | 100% | −3.54pp |

在 256 文档确认上，主方案额外逻辑读少 **60.62%**、总逻辑 KV 读少 **23.21%**、ANLS 相对全精化低 **0.31pp**（区间 [−0.82, 0.17]）。

**读法**：读轴**已有可用空间**（省一大半额外读只掉半个点），但"0.5pp 非劣"还没证明（差 0.09pp）；且这个量是**声明的 tensor payload + 选择开销**，不是物理 HBM 流量。

## 5. 被推翻或被修正的判断（核心章节）

> 这一节是本项目的"负结果资产"。每条都写明：曾经怎么想、什么证据推翻了它、现在应该怎么写。

| # | 曾经的判断 | 推翻/修正它的证据 | 现在正确的写法 |
|---|---|---|---|
| 1 | "比最强对照高 +2pp ANLS"可作目标 | 最强直接对照 Native4 与 FP16 只差 0.26pp（88.48 vs 88.74），在 256 文档上甚至反超 FP16 0.30pp；真正有空间的 2-bit 档（Base2）距它 2.1–3.9pp | "在最强对照之上再要 +2pp"**在这个工作点是天花板效应**，不是难度问题（`docs/ERRATA_ARP_v1.0.md` E4 早有同判：FP16 0.332 vs KIVI2 0.324，只差 0.8pp） |
| 2 | "V 的误差跨轮才结账，所以多轮会复利" | base2 首轮 gap 2.79pp、6 轮不增长；四臂历史介导只有 1/13 | 从论文动机里**删除**，降为待测假设 |
| 3 | "末层 margin 能预测压缩损伤" | 在 Base1 上**由压缩直接造成的负翻转子集**里，margin 的 AUROC 只有 **0.4869**，区间 [0.3806, 0.5901]（等于抛硬币）；注意它与"一般任务错误 AUROC 0.7592"不是一回事，后者只反映题目难易 | 末层不确定性可以当**便宜的一般错误信号**，但**不是压缩误差的指示器**（`docs/EXPLORATION_MARGIN_AND_FIDELITY_DEV8.md`） |
| 4 | "早层 Δ_probe 双读能定位该精化的位置" | 600 个响应 **0 次 argmax 翻转**；986 个探针中 960 个请求升级 | 表征位移大**不等于**精化有实际收益 |
| 5 | "读调度/触发器能追回大部分损伤" | CLEVR 64 图×10 问×19 配置共 12160 回答，没有触发器稳定胜过简单控制；预设 Probe7 相对周期精化 −0.3125pp、区间 [−1.7188, +1.0938]、Holm16 **p=1**；Doc 未来收益表探索 +2.43pp，确认集只 +0.137pp、区间跨 0 | 主力从"何时多读"转向"表示丢了什么"；读轴只保留为**低成本剂量实验** |

| 7 | "1-bit 失效是信息论极限" | 同字节只换电平：0 → 28 → 56.76 → 62.98；确认集 30.48 → 60.15 | **可修复部分很大**，且修的是重建常数，不是信息量 |
| 8 | "失效 100% 是秩一（范数）问题，补一个 per-token 增益就够" | 四臂：真实方向 +18.56pp，真实范数 +15.46pp；误差能量角度项约 94%、径向约 6%；组内范数相关仍有 0.69/0.73（范数没被压成常数，只是动态范围被压扁）；四臂有交互 | **方向是主因、范数是次因但不可忽略**；不得用差值算"解释百分比"，也不得再说"秩一失效" |
| 9 | "`SNR=σ_k/σ_ε>1` 是可用性门槛，SNR>5 保 top-1" | 元素 MSE 几乎相同（0.60 vs 0.58 σ）却差 37.5pp；量化误差与信号强相关，不是独立加性噪声 | SNR 只能当**序参量**，不能当质量公式；门槛必须**由实测曲线定** |
| 10 | "1.25 / 1.31 / 1.09 bit 是推导出的最优码率" | 这些数是"payload 1 bit + 元数据 0.25（+ 增益 0.125）"的**编码记账**；元数据本身不是免费的 | 写成"若干**编码成本点**"，不写"理论最优" |
| 11 | "元数据可以先无损省掉（0.25→0.025）" | 同样未校准：g128 **85.75** vs 整图分组 **83.02**，元数据压缩自带 −2.73pp | **分组、重建目标、模型使用方式必须联合检验**；先省后修不免费 |
| 12 | "压缩状态条件校准（cold）一定胜过 warm" | 换新 32 校准源文档 + identity 初始化 + 多 token 目标后差别缩小；warm 联合版本也可以更好 | 不主张 cold 恒优；按本轮冻结方案报结果 |
| 13 | "只保护问题 prefill 就足够" | 开发集有此现象，256 文档确认**没有复制**（−1.44pp） | 写成"开发集观察，未复制" |
| 14 | "动态选择一定不如周期精化" | 确认口径下周期 −2.00pp、risk −0.59pp | 读轴排序**随剂量与阶段变化**，不能一句话定论 |
| 15 | "少读字节 = 更快" | risk 少读 78.56% 却慢 12.4%；周期少读 75.03% 只快 6.9% | 逻辑读量**不等于**加速；选择开销必须计入，且要研究跨 decode 复用 |

## 6. 现在站在哪（能力边界）

**已经建立的能力**

- 完整、可审计的低比特视觉 KV 执行链（真实 packed、真实资源账、冻结契约、独立 owner 公式核验）。
- 一条**可复现的机制诊断链**：电平阶梯 → 范数/方向四臂 → 状态形成对照，三者在不同数据集上互相印证。
- 一条**已经确认的表示收益**：1.695 bit 追到 Base2 −0.89pp（省 24.75%），并在 256 文档上确认方向码对同价 Lloyd +3.35pp。
- 一条**已经确认的读取收益**：额外逻辑读省 60–79%、质量掉 0.3–0.6pp。

**尚不具备的能力（写论文前必须承认）**

| 缺口 | 现状 | 差多少 |
|---|---|---|
| 距强参考 0.5pp | 主方案距 Native4 4.1pp（64 图阶段 7.35pp） | 差一个数量级 |
| 读取非劣区间 | [−0.82, 0.17]，差 0.09pp 到 0.5pp 容差 | 未证明 |
| 端到端加速 | 无任何配置快于 FP16 | 反而慢 6–12% |
| 跨数据集泛化 | TextVQA 上方向码 −10.00pp | 机制成立、实现未泛化 |
| 整模型显存下降 | 峰值仍被原生图像 prefill 占据 | 不能宣称 |

**不可宣称的三句话**（审稿人一问就破）：①"我们把整模型显存降到了 X%"；②"读字节下降带来加速"；③"1-bit K 已被解决"。

## 7. 未决问题与下一步

**下一轮优先（按当前证据的边际价值排序）**

1. **用省出的比特补"真实内容误差"**：约 1.58 bit 底座距 1.8 还有 ~0.22 bit 空间，做**等字节的 K 残差 / V 残差与均匀控制**，判断边际收益落在哪一侧。层×KV-head 索引便宜，**残差本体必须完整计费**。
2. **分开"偏置"与"方向"损伤**：查压缩后重建均值偏移、视觉/文本段相对偏置，试少量更高精度均值或重建偏置校正。固定 query 的视觉排序与整模型答案**不是同一个目标**（尚未实现，无结果）。
3. **补齐读取剂量与阶段组合**：更高读取剂量、prefill 保底 × 影响选择、以及**跨 decode 复用选择结果**（这是把"少读"变成"少等"的唯一现成路径）。
4. **状态匹配 × 答案轨迹校准**：把第一 token 词表 KL 扩展到 FP16 自生答案前若干 token 的 KL；同时比"只学 scale"与"同时学 center"，单独消融初始化、校准条件、参数量。
5. **大数据集基准押后**：TextVQA 5000 问、8 方法（约 4 万次回答）数据与哈希已备好，**在方法定型后再跑**，现在跑只会烧时间。

## 8. 名词表

| 词 | 含义 |
|---|---|
| **packed / 真实打包** | 读写的是压缩后真实字节码，不是解压出来的浮点原型 |
| **材料化（materialized）** | 为诊断把量化值还原成 FP16 张量；性能单列，不进部署表 |
| **cap8 / cap16** | 视觉 token 上限档位（约 8 或 16 个 448×448 tile） |
| **g128 / 整图分组** | 量化元数据每 128 个 token 一组，或每通道跨整图一个 |
| **Lloyd / MAD / min-max** | 三种 1-bit 两电平重建：组内拟合两质心 / μ±平均绝对偏差 / 组内极值 |
| **范数 × 方向四臂** | A00/A10/A01/A11：分别修"长度""指向""两者"，用来做因果分解 |
| **状态形成（state formation）** | 问题 token 的隐状态是通过高精度还是压缩前缀算出来的 |
| **额外读 / 总读** | 只读残差的字节 / 含 base 在内的全部 KV 读字节 |
| **soft VQA accuracy** | TextVQA 官方 10 标注的软匹配准确率，与 ANLS 不同 |
| **owner 公式** | 独立实现的字节归属计算，用来核验"省了多少" |
