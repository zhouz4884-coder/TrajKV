## 2. 谱截断这条路应该关掉，而且我们自己的数据关得很干净

上一轮我押"按 $\Sigma_q$ 谱分配比特"，理由是全仓库没做过。这一轮做完了，结果在 `norm_dev16_analysis/summary.json`，同一 16 图 62 问、同一材料化口径：

| 变体 | ANLS | rank | 编码 |
|---|---:|---:|---|
| `pq_fwht`（不选方向，固定正交 + 均匀） | **92.58** | 128 | pq |
| `pq_query_aware_mixed`（按 query 选） | 91.17 | 128 | pq |
| `pq_random`（随机正交） | 89.61 | 128 | pq |
| `pq_k_pca`（按 K 方差选） | **82.58** | 128 | pq |
| `project_query_r64` | 91.22 | 64 | 截断 |
| `project_query_r32_norm` | 89.90 | 32 | 截断 |
| `project_query_r16_norm` | 36.90 | 16 | 截断 |
| `project_query_r8` | 14.88 | 8 | 截断 |

**这是一个单调的、四个台阶的排序：不动方向（92.58）> 按 query 选（91.17）> 随机（89.61）> 按 K 方差选（82.58）。**

三条结论，都和我上一轮的预期相反：

**(a) 按 K 自身的方差选方向是主动有害的，掉 10pp。** 因为 K 的高方差方向往往是"所有 token 共同偏高"的通道，它对**区分 token** 没有贡献；PCA 把比特留给它，等于把比特花在 softmax 看不见的地方。这是 `f(r)` 这个判据的第一次实测反例。

**(b) 截断是悬崖，不是缓坡。** r64→91.22、r32→89.90、r16→36.90。而谱能量占比在 r16 还有 **0.976**（prefill）/ 0.932（decode）。**97.6% 的分数方差保住了，答案崩了 55pp。** 所以"能量占比"这个量作为判据彻底作废——它度量的是外积的迹，不是 top-1 的序。

**(c) query-aware 比 K-PCA 好 8.6pp，但仍不如不选。** 两个原因，第二个我上一轮就警告过：白化 $\Sigma_k^{-1/2}$ 会放大 $\Sigma_q$ 小的方向的噪声，而那些方向恰恰是 $\Sigma_q$ 估计最不可靠的地方。**ridge 混合也只是把 91.17 拉到"接近但不如"。**

### 为什么截断必然失败：一个一行的推导

分数 $z_i=q\cdot k_i$。截断后 $\hat z_i = q\cdot P_rk_i$，误差 $\delta z_i = q\cdot P_\perp k_i$ 是**逐 token 不同的**（依赖 $k_i$），不是共同偏移。而 softmax **只对共同偏移免疫**：

$$\delta a_i = a_i\Big(\delta z_i-\sum_j a_j\delta z_j\Big).$$

所以 4% 的分数方差被丢掉，等价于给每个 token 的 logit 加了一个 4% 的独立扰动。**而 top-1 与 top-2 的间隔在 1792 个 token 上通常远小于这个扰动的标准差。** 结果就是报告 §3 里那句"prefill 时 r16 的 score MSE 0.569 小于 PQ 的 0.737，但联合读出相对 MSE 0.120 对 0.089"——**分数更准，读出更差**，因为分数准不准由 MSE 算，答案准不准由 top-1 算。

**判据修正（这条要写进方法节）**：K 的编码目标不是 $\mathbb E\|\delta z\|^2$，而是

$$\Pr[\arg\max_i \hat z_i \ne \arg\max_i z_i]\ \approx\ \sum_i a_i\,\Phi\!\Big(-\frac{\Delta_i}{2\sigma_{\delta z}}\Big),$$

其中 $\Delta_i=z_i-\max_{j\ne i}z_j$ 是间隔。**保排序的本质是保"间隔相对于误差"，不是保方差。** 这个量在离线十分钟可算（`fixed_query` 的表里已经有 $a$ 和 $z$），不需要跑答案。

## 3. 那我们该信什么：softmax 平移不变给出的 K/V 不对称

报告 §3 有一个数字被写在很后面，但它可能是这一轮最重要的：

> cal16 的同 q 局部输出误差能量，**V 25.44 万、K 10.47 万**。

V 的误差能量是 K 的 **2.43 倍**。而 `joint_rate` 在总 1.5 bit 的预算下算出的最优分配是：

$$\text{K}=0.598\ \text{bit},\qquad \text{V}=2.402\ \text{bit},\qquad V_{\text{shift}}=+1.402.$$

**当前是 K=2.0 / V=1.0。闭式解要 K=0.6 / V=2.4，方向差了一个数量级的符号。** 而报告 §1 的实测（V 残差 90.771 > K 残差 88.576）**独立地指向同一个方向**。

这两条互相独立：一条来自率失真模型，一条来自真实答案。它们对上，说明这不是噪声。

### 为什么会这样：K 的误差被 softmax 的平移不变性压缩，V 的不会

设 attention 权重 $a_i$、集中度 $C=\sum_i a_i^2$、三阶量 $S_3=\sum_i a_i^3$，K 的量化误差引起的 logit 扰动 $\delta z_i$ 在 token 间独立、方差 $\sigma_z^2=\sigma_q^2\sigma_{\varepsilon_K}^2$。

**K 的误差只通过 softmax 进输出**：$\delta a_i=a_i(\delta z_i-\sum_j a_j\delta z_j)$，于是

$$\mathbb E\|\delta a\|^2=\sigma_z^2\sum_i a_i^2(1-2a_i+C)=\sigma_z^2\big(C-2S_3+C^2\big).$$

括号在"attention 完全集中"时（$C\to1,S_3\to1$）**恰为零**——softmax 已饱和，K 怎么抖都改不了 $a$；在均匀时趋近 $C$。

**V 的误差直接进输出**：$\delta o=\sum_i a_i\delta v_i$，$\mathbb E\|\delta o\|^2=\sigma_{\varepsilon_V}^2\,C$。

两者对输出的贡献之比（$v_i$ 近似独立同分布，$\|v\|^2$ 约去）：

$$\boxed{\ \frac{\text{sens}_K}{\text{sens}_V}=\frac{\sigma_z^2}{\sigma_{\varepsilon_V}^2}\cdot\frac{C-2S_3+C^2}{C}\ }$$

- **均匀 attention**（$C=1/N$）：比值 $\approx\sigma_z^2/\sigma_{\varepsilon_V}^2$ —— KIVI 的世界，K 和 V 同权、甚至 K 更重要（因为 $\sigma_z$ 大）；
- **高度集中**（$C\to1$）：比值 $\to0$ —— **K 免费，V 是唯一瓶颈**。

**这就是 KIVI"K 要 per-channel 高精度、V 可以粗"在 VLM 上反转的原因**：语言模型的 next-token attention 相对分散，视觉 patch 的 attention 极度集中（一个 patch 常常吃掉 30–60% 的 mass）。KIVI 没有错，它只是没覆盖 $C\to1$ 这一格。

**而 $C$ 可以逐层测。** `joint_rate` 的 per-layer 结果已经显示 K 的最优比特从 0.33 到 1.15 跨 3.5 倍、V 从 1.85 到 2.67 跨 1.4 倍——**层的异质性主要在 K 侧**，这与"某些层 attention 更集中"一致。

### 反过来用联合水位反推 $C$：它给出一个当天可验的数

同水位下 $b_i=\frac12\log_2(\mu_i/\theta)$，所以 K 与 V 的平均比特差直接给出两侧的度量比：$b_K-b_V=-1.80$ → $\mu_K/\mu_V=2^{-3.6}\approx0.083$。把它代回

$$\frac{C-2S_3+C^2}{C}\approx0.083$$

数值扫一遍：$a=(0.96,0.04,\dots)$ 给 0.0016（太集中，不符）；$a=(0.9,0.05,0.05)$ 给 0.026；**$a\approx(0.8,0.1,0.1)$ 给 0.10**——恰好在量级上。

**所以这个模型预测：视觉段平均 $C\approx0.6\text{–}0.7$，即 top-1 token 吃掉约 80% 的 attention mass，有效 token 数 $1/C\approx1.5$。**

这是一个可以当天算出来的数，而且它是**唯一能把"V 该拿 2.4 bit"和"K 免费"这两件事同时解释掉的量**。如果实测 $C$ 落在 0.3 以下（top-1 只占 55%），那 §3 的机制就解释不了 4 倍的比特差，得另找原因；如果 $C>0.8$，那说明比预想的更极端，K 可以直接砍到 0.3 bit。**两种结果都比现在继续调排序器有用。**

## 4. 下一步：一次等预算的搬运，不用加一个字节

把上面三条合起来，下一轮的主实验只有一个，而且它不需要新比特：

$$\text{from}\quad K=2.0,\ V=1.0 \qquad\text{to}\qquad K\approx0.6\text{–}1.0,\ V\approx2.0\text{–}2.4.$$

**但 K 的降比特必须用"更小的码本"，不能用"截断维度"**——这是 §2 的直接推论。当前 K 是 256 码字 × 4 维（2 bit/元素）；0.6–1.0 bit/元素对应 **8–16 码字 × 4 维**。码本变小只是误差变大，不丢方向；截断是丢方向，必崩。

这条预测可以写成三个可判的臂：

| 臂 | K | V | 预测 | 若不成 |
|---|---|---|---|---|
| 现状 | 2.0（256×4） | 1.0（per-channel） | 87.2 底座 / 90.8 加残差 | — |
| **A（搬运）** | **1.0（16×4）** | **2.0（2 bit per-channel）** | **≥91.5 @ 同总字节** | K 降到 1.0 掉 >2pp → 用 1.5/1.5 折中 |
| B（激进） | 0.6（8×4） | 2.4（2 bit + 残差） | ≥91.5，字节更少 | K 0.6 崩 → 退回 A |

**为什么我认为 A 会成**：三个数字已经各自独立指向它——V 误差能量是 K 的 2.43 倍、联合水位要 V 拿 80% 的 payload、V 残差比 K 残差高 2.2pp。如果 A 不成，那说明"率失真模型 + 误差能量 + 残差干预"三件事同时错，这本身也是必须知道的结果。

**同时必须补的两个对照**（现在缺，缺了论文会被打）：

1. **Text 上的均匀 1.8 bit**。主候选在 Text64 是 72.969、Base2 是 75.469。如果"均匀 1.8"也是 72–73，那结论是"场景文本在 1.8 bit 上就是不够"，不是"我们的表示错"；如果均匀 1.8 有 75+，那才是表示问题。**这个对照半天，它决定这轮外效度怎么写。**
2. **单元覆盖率的剂量曲线**。§1 里"分散 87.885 < 随机 88.212 < 集中 90.771"这个 2.9pp 的梯度，比排序器之间的 0.1pp 大 30 倍，**它是这一轮真正的机制发现**。值得单独扫：同一批单元，覆盖率 $p\in\{0.25,0.5,0.75,1.0\}$。如果 $p=1.0$ 远超线性外推，说明**一个单元的残差"要么做全、要么不做"**——原因是未修的 token 仍然参与 softmax 归一化，会把所有 query 的 attention 拉偏。**这条能给论文一个"为什么必须集中"的定量解释，而现在的报告只报告了现象。**

## 5. 论文该写成什么

现在有两条路：

**路 1（弱）**：`我们提出了一个基于输出收益的残差分配器，在 1.8 bit 下比 Base2 高 3.6pp。`
——会被 RateQuant / KVTuner / HeadQ 三篇分别打掉，而且我们自己的匹配交换是反的（§1）。

**路 2（强，我主张这条）**：`极低比特视觉 KV 的瓶颈位置由 attention 集中度决定：K 被 softmax 的平移不变性保护，V 没有。给出判据 $\text{sens}_K/\text{sens}_V$，据此在 1.8 bit 下把比特从 K 搬到 V，同字节 +3.6pp。并且证明"按分数谱选方向"在视觉 KV 上不成立（K-PCA −10pp），因为它保的是方差不是序。`

路 2 的每一句都有我们自己的数据：

| 主张 | 证据 |
|---|---|
| K 被平移不变性保护 | $C-2S_3+C^2$ 的推导 + V 误差能量 2.43×K |
| V 该拿 80% payload | `joint_rate` K0.598/V2.402，且实测 V 残差 > K 残差 2.2pp |
| 按谱选方向有害 | FWHT 92.58 > query 91.17 > random 89.61 > K-PCA 82.58（同 16 图） |
| 覆盖必须集中 | 集中 90.77 > 随机 88.21 > 分散 87.89 |
| 判据是序不是方差 | r16：能量 97.6%、答案 36.90 |

**这四条里没有一条需要"我们的估计器比别人好"，所以它不会被"这是个组合"打掉。** 它是一组关于"极低比特视觉 KV 的瓶颈在哪里"的测量 + 一个由此推出的配置。

**和已有工作的分界要写清**：KIVI 给了轴（per-channel K / per-token V）但没给"何时该反"的条件；Palu 用低秩 + 量化，而我们的数据显示低秩 K 在视觉上掉 10pp；HeadQ 用 query 基算残差分数，我们测了 query-aware 在材料化条件下输给 FWHT；RateQuant/KVTuner 用输出误差/梯度引导，我们复现了它们的排序但发现它与随机在统计上不可分。**它们各自占了一个单点，我们给的是"这些单点何时成立"的条件。**

## 6. 我建议的顺序（三天）

1. **D1 上午**：算每层的 $C=\sum a_i^2$（`fixed_query` 的表里已有 $a$），和 `joint_rate` 的 per-layer K 比特做相关。**如果 $\text{corr}(C, b_K)<0$ 且明显，§3 的机制成立，主线锁定。** 这个不用 GPU。
2. **D1 下午**：Text64 上补"均匀 1.8 bit"对照，定性外效度。
3. **D2**：臂 A（K 16×4 = 1.0 bit，V 2 bit）在开发 64 上跑。**这是下一轮唯一的主实验。**
4. **D3**：覆盖率剂量曲线 $p\in\{0.25,0.5,0.75,1\}$，给"集中"一个定量解释。若 A 成，同日上臂 B。

**如果 A 不成**，退路不是回去调排序器（已经证明无预测力），而是**转成测量论文**：把 §3 的判据在 3–4 个模型/任务上验证，主张变成"极低比特视觉 KV 的瓶颈定位规则"，仍然成立，只是没有新方法。这条退路比硬撑一个估计器好。

## 7. 三条我认为必须撤回的旧说法
