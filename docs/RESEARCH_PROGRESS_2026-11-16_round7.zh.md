# Round7：更低码率已可用，反馈重估尚无独立增益

本阶段按讨论第二十二节执行，研究执行与复核已完整完成。两张RTX3090运行完整FP16模型与真实packed视觉KV；模型、图像、结果和新编译缓存使用数据盘。实现、开发迭代、两个骨干的新来源确认及同输出成本均已完成；GitHub同步以本轮release的独立远端交付receipt为准。

最有用的进展是一个新的约**1.295bit/视觉KV元素**工作点：新Doc128得到**97.680 ANLS**，新Text128得到**80.938%官方soft accuracy**。相比约1.8bit原分配，完整视觉KV少约28%，分别付出0.464pp和1.406pp质量差距。相比本项目KIVI式base2，少约42.5%字节，Doc高1.041pp、Text低0.156pp。它支持继续研究更低码率，尚未达到相对Native4两域均差≤0.5pp的质量标尺。

另一个明确发现是：当前所谓“接受后重估”的最终分配，可以用**初态静态分数＋相同批内选择约束**精确复现。因此其效果不能单独归因于反馈重估。我们保留实际结果，也保留这个更简单、无需重复执行GPU的等价对照。

## 1. 方法、数据与完整成本

新实现包括G4_256同码率的LS幅度、块重选码、query-rank-one度量和projection幅度；另实现G4_16真正nibble-packed reader，每个K token的索引由32字节变为16字节。K/V基码覆盖全部视觉token，按实际预算仅保存可用残差池；部署不保留原始FP16视觉K/V。低码率主候选保留43个一级残差，不能把其总效果说成完全无精化的K1/V1。

完整账含码流、均值/增益、V质心、码本、位置、残差、lookup、排序、policy和encoder参数；不重复加`total_unique`。表中的bit是实际owner相对全部视觉K/V元素的加权值，不包含模型权重与FP16文本KV。主确认K1各会话的完整bit为：Doc均为1.29466，Text为1.29466–1.31329；Text表值1.29579是加权工作点。详见[方法与口径](METHODS_ROUND7_2026-11-16.zh.md)。

旧Doc64/255问和已观察Text64用于开发。新策略选择使用Doc16源/38独立问题、Text16源/22问题；Doc源曾参与旧factor校准，只对本次拟合留出。交换校准实际使用4个Doc源＋4个Text源，共14问，不能把准备好的32源池说成全部已拟合。

九个主方法在确认前冻结，之后物化新Doc128源/412问与Text128源/128问，执行2,304次自由会话、4,860个回答。Doc来自额外官方**train**分片，按历史来源和原图SHA排重，是project-fresh派生确认集，不是标准官方测试集，也不保证基础模型预训练未见。该Doc队列Full接近ANLS天花板，不能将98分外推为完整DocVQA基准成绩。全量审计对齐128张原图与全部412问，并独立重算3,708个回答；没有发现映射、答案拼入输入或评分实现错误。[冻结身份](../audit/a2/round7_method_freeze_v1.json) · [数据传输核验](../audit/a2/round7_confirmation_transport_v1.json) · [Doc全量对齐与高分核查](ROUND7_DOC_CONFIRMATION_ALIGNMENT_2026-11-16.md)

## 4. 连续诊断与机制边界

K1校准GT NLL从0.453108降到0.242635，但89.3%的净收益集中在两个Text来源。删除这两个来源后的固定policy收益仍为正，但这不是删源重新训练。K1的GT与Full自目标选择run中，四份对应policy文件全部字节相同；Text校准的六问中五个完整目标相同，另一问共享前四个token，不能把两种模式叫作独立复现。

初态16个singleton＋baseline，或8个joint＋baseline，在相同每批最多一对的约束下，都可复现当前分批policy。实际完整campaign包含共享复用及三策略诊断，物理调用数与单臂逻辑上限另列，不能宣称它们的端到端校准成本相同。[干预分析](ROUND7_CONDITIONAL_DIAGNOSTICS_2026-11-16.md) · [精确等价检查](../audit/a2/round7_matched_static_batch_equivalence_v1.json)

112个相关head上的query二阶矩top1占比中位约0.676；以head×source×query为描述单元，现码误差的native-bridge WHT投影比例ρ在prefill/decode的中位为1.011/1.009，独立来源只有8图。谱集中与误差如何投影是不同测量；ρ接近1不能推出所有同格式优化均无效。首个profile调用有明显冷启动/host gap，稳态判断使用后续同输出预热测量。[诊断与profiling](ROUND7_METRIC8_PROFILE2_DIAGNOSTICS_2026-11-16.zh.md)

## 5. 论文判断与下一步

保留“更低码率基码＋可计费覆盖”作为性能主线。当前1.3bit点的存储下降真实、两域质量代价不同，下一步优先补Text差距。没有数据支持把“反馈重估必要”“ρ阈值决定是否研究”“SNR闭式给出最优bit”写成论文结论。

可执行的下一轮先扩充来源多样的校准，使用匹配批内约束的简单静态方法作直接对照；目标看完整序列，保留高置信首token却后续读错的情况。编码侧可以探索小码本的headwise适配，并固定残差覆盖单独检验，再做预算重分配；这与旧G4_256码本校准有历史联系，不能叫作从未做过的全新部件。已有工作提供可组合组件，新增价值需要受控的端到端增量。[原始文献定位](LITERATURE_2026-11-16_round7_encoding_and_exchange.md)

当前结果支持继续探索这个低存储前沿，尚不足以把现有调度/重估程序直接写成论文核心算法。下一步不重启5000问大跑分，也不再扩展margin触发器；优先做能减少Text损伤的少量新编码与多源校准实验。
