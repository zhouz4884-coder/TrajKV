# Round6 hash verification

The original `source_sha256` identifies preserved private source bytes. `public_sha256` identifies exact derived export bytes: for members of `ROUND6_SOURCE_INDEX.json`, verify the bytes extracted from the release ZIP. Entries generated only for the repository, including the README, describe their pre-Git generated bytes and are not claimed to be ZIP members.

This repository's `.gitattributes` normalizes text to LF. A Git blob or GitHub Raw download can therefore have a different SHA256 from the pre-Git CRLF export without changing its numerical data or program text.

[`ROUND6_GIT_CONTENT_HASHES.json`](ROUND6_GIT_CONTENT_HASHES.json) records the committed content of the completed Round6 snapshot `a84232012c8654fd5bf800f2fe2490fb704646c0`. Use `git_blob_content_sha256` for plain committed-file bytes and `git_blob_oid` for the Git object identity. The reference is pinned; subsequent publication-documentation changes on `main` are outside that captured snapshot.

The release ZIP, source index, original source/public digests and historical release tags are preserved. This note clarifies hash scope; it does not revise research results.
