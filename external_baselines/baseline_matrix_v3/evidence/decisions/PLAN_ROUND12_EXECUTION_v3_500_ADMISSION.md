## 执行身份与覆盖

当前low：`r7_joint_k1_gt_cond`；high：`r7_budget_k2_cond`。不用旧inc配对代替。实际low为原K23/V20具体43槽；high随N实际26–44，覆盖与low不同。

所有新固定覆盖表示端点采用manifest记录的low具体43条(axis,layer,head,depth)，保原完整priority与f0数值。改变的轴真实重编码其残差；其它轴的字段保持。A不是旧R7high，A与旧high差不能归为单个V残差。

固定43控制不冒称逐题严格1.8bit，尤其小N。报告固定为两层：①表示控制表使用原low具体43覆盖，比较A/B/C/D/G8/R并明报完整费用；②质量—真实资源部署表保留原low、原high各自原覆盖及新候选合法配置，逐请求报告完整费用与覆盖。不同覆盖可以并列，不能声称单因素等价。不为统一表格另加160个旧high前43回答。

A与原high均为K2/G4_256、32B/token/head，两者间没有16→32B的K索引变化；差异来自具体覆盖及槽数。严格部署预算另用完整owner求可负担槽数，覆盖变化独立报告。

### C/D的V选择规则

首版固定使用**每图自适应mask**，不是校准期一次性全局mask。每个(layer,head)有128bit mask，明确每图1792B；不按token增长。这样避免把固定mask泛化问题与V减比特问题混为一谈，也不需要未来问题或答案。

当前V的minimum/scale是每图计算的每通道两个FP16槽，全模型57,344B/图，已包含在原owner；它们不是冻结全局资产。保留通道维持原两个槽，并紧凑存64通道payload；丢弃通道不存payload，把同两个槽改为(minimum=mu, scale=0)。decoder只读mu，不需要p、旧minimum/scale或原图；不额外存一份p/中心数组。mask仍1792B/图。

选择规则在真正Half reader端点上定义：a0=Half(Half(0*scale)+minimum)，a1=Half(Half(1*scale)+minimum)，p为当前图像1码频率。encoder计算mu=Half((1-p)*a0+p*a1)，用N*p*(1-p)*(a1-a0)^2或实际Half SSE差选择代价最大的64通道。decoder的dropped分支直接返回存好的mu。中心与zero-scale元数据按实际f0折叠后的帧写入，f0只应用一次。

N*p*(1-p)*scale^2是实数近似，不拿它代替Half路径数值验收。原20条V残差覆盖全128维，针对新base重编码。此规则是base可加失真准则，不是最终任务或带残差的全局最优保证。

固定校准mask留作后续可选简化，不与首版结果混合。若未来使用固定mask，应按校准图像的Delta加权求和，不将跨图平均p直接代回非线性公式。

## 信息动作

共用低档probe。首版用同一已可见问题状态采集首1/首3token信号；任何动作前回滚probe文本状态，再从对应原问题生成最终回答。probe另记token数、forward与耗时。

- P：**现场重新prefill原图、构建冻结原high、替换低档后重放问题**。首版不混用Host预存合同；重prefill/编码/切换峰值全部计费。以后Host高档或共享K字段属于单独优化版本。
- Z：原图＋一个相关局部放大图，完整生成原生多图前缀，全部视觉位置真实压成R7低档字段后回答。
- Z-random：随机同面积、同形状ROI，与Z保持模板、实际tile数、编码和回滚流程一致。

先固定一个无需额外模型的定位器：采集低档原始问题token span最后至多4个非特殊token、最后6层query，按真实reader坐标和GQA规则获得视觉空间图，各层/head/query等权汇总。tile映射回原图；thumbnail单列。标出实际问题span和采集token，不能误用统一回答指令末尾作为问题内容。

ROI约为原图1/16面积。若旧非thumbnail网格B块，采样密度比近似`16/B`，实际grid、bbox、resize和是否仅上采样都记录。一个448tile为256视觉token；crop只生成一个实际tile，出现额外thumbnail按实际数量处理并另立配置。

第一版Z使用完整多图重建，不直接拼两个独立KV。当前单图入口与视觉owner分类需新增研究版本；新增视觉状态不能全部落入text字段。如果临时留FP16 crop，256token为14,680,064B，不能按低比特账记。初版目标是全部视觉状态真实packed，原FP16视觉cache按合同释放。

Host存档、GPU常驻、全请求峰值、PCIe传输、编码/probe/动作/最终生成时间分列。逻辑选中owner均值不能替代这些实测。对象一次性提升与逐请求反复升降档合同不混用；同一图片多问题复用时明确摊销次数，单次VQA先报不摊销成本。

## 两卡队列与1200回答开发预算

第一阶段：

| 工作 | 来源 | 新终止回答 |
|---|---|---:|
| GPU0：A/V2R/D | main160各一臂 | 480 |
| GPU0：B/C四格补充 | factorial32各一臂 | 64 |
| GPU1：P/Z/Z-random | actions96各一臂 | 288 |
| GPU1空档：mass-only/route-only oracle | oracle24各一臂 | 48 |
| 合计 |  | 880 |

oracle是超预算整模型诊断，不进方法表。B/C的32来源与其它端点同题；D−A是部署点比较，B−A、C−A与四格交互只作有限范围归因，不据此宣布全模型机制。

第二阶段必保：

- G8与R各跑middle64，共128个新回答。
- C从factorial32扩到C96，只跑64个新增来源。
- 累计1072回答。由此保住G8/R等预算控制，也有C/G8共同64来源。

最后128个回答按开发结果选择一个扩样分支，写明决策后才生成新增输出：

1. 若B的高档容量收益可能成为实际前沿、且32来源不足判断，则B从32扩到main160，新增128；累计1200。
2. 否则把G8/R各从64扩到middle128，各新增64；累计1200。C/G8此时共有96来源。

这是开发阶段的有界调度，不把小面板无显著性当作封口，也不在新确认数据上按p值选择队列。接近且影响晋级的结果优先扩样；任何后续新增开发范围都记录为新修订，不偷偷覆盖本稿与原样本。

两卡任务按实际实现就绪顺序排：GPU0先A/V2R，D的10bit/紧凑V路径验收后接入；GPU1的信息动作不等新book。G8新reader同样不作为其它动作的前置。

## 校验与统计

使用完整模型原FP16权重、greedy seed0/max_new64、原全图cap8与冻结本域评分器。真实模型/processor/scorer/reader/书/样本在新run运行前形成源码和资产seal。数值冒烟与owner验收完成后再跑自由回答；不将代理、CPU分析或TF算作真实任务回答。

新终止回答、probe、码本训练、TF、编译、旧参照视图分别计数。所有指标可从原始预测重算。失败与修复用新run保留证据；不改早期launch_remote.py、remote.py及冻结bridge。

配对结果按源/文档聚类；主要看Info ANLS，Doc/Text分别报告；重建MSE、KL、eta是解释量，不折算成已测任务收益。C使用的top64中心编码不能用g16_256的RD当实测值。近似差值不直接宣布等效或关闭ratio。

**开发功效定位：** 32来源四格是有限精度的先导任务对照，不仅是管线测试，也不足以确认1pp左右的小收益；64/96/128同样不默认足够。可以观察大改善或灾难性损伤、差异分布和翻转模式，保留均值、配对区间、方差、改善/恶化数及实际费用。不得由不显著作失败或等效结论，也不将点估计排序当成可靠真排序。结果接近且影响晋级时，使用已定扩样分支。

DS的MDE=2.80*s_delta/sqrt(n)是双侧alpha=.05、80%功效及独立配对近似下的规划值。官方fixed500的low-high差分Info标准差约31.25pp，确实给n64约10.94pp、n128约7.74pp；但这是那一对方法的方差，不是全部新候选共同的检测下限。新候选应估计自身配对差分的源级波动；存在源内多问题时使用聚类设计。当前官方fixed500每域恰为500个唯一图像/来源，不由此推定未来面板也如此。
