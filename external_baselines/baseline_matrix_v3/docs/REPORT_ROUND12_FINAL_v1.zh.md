# Round12：基础编码容量、残差覆盖与问题条件取证

日期：2026-11-24。已完成开发1200次计划内GPU自由回答及冻结R在InfoVQA、DocVQA各500题的真实端到端比较，另2个早期pilot单列。**得到一个约1.55bit的中档点：Doc点估计略高于R7高档且视觉缓存更小，Info仍低于高档，因此保留R作为中档资产，尚不全面替换R7高档。** 两张3090运行，未跑完整5000。

## 研究问题与实际工作

本轮直接检验：在固定模型与图像密度下，视觉KV的有限字节应购买更细的K方向码字、更多残差覆盖，还是在问题到来后购买新的局部图像证据。没有把连续误差下降预先等同于答案改善。

使用完整InternVL3-8B-hf（7,944,373,760参数，原始FP16权重），两张RTX3090并行进行真实packed reader端到端自由生成。greedy、seed=0、max_new_tokens=64，原图cap=8；文本KV仍为FP16。模型、数据、结果和所有新增编译/临时缓存均放项目数据盘。CPU用于配对分析、离线官方评分和证据核验，不替代新方法的GPU回答。

计划内开发共1200个新终止回答：1152个可执行表示/信息动作回答，加48个明确超部署预算的机制oracle回答；此外保留2个早期协议pilot，单独计数并排除正式质量表。这些回答最多来自160个不同开发来源，不能称作1200个独立样本。校准、teacher forcing及kernel数值检查另计。

## 表示和信息动作

各表示均使用实际打包的索引、元数据和残差，完整计入独立tensor storage。改变base的轴从原生FP16状态重新编码残差，没有把旧sign码直接贴到新base。

| 配置 | 实际改变 | 要回答的问题 |
|---|---|---|
| A | K采用G4_256，V保持原V1，保留原low的具体43槽 | 同覆盖下提高K容量的参照 |
| V2R | K保持G4_16，V改校准四电平 | 增加V容量是否优于近同费用增加K |
| B | K采用G4_1024的真实10bit索引 | 继续增加K方向容量是否有效 |
| C | K2；V每个layer/head紧凑保留64通道，余通道用已存中心 | 是否可用V字节补贴K |
| D | K2.5＋上述V0.5 | 近等payload下的非对称交换 |
| G8 | K采用G8_4096的真实12bit索引，V1 | 均匀中档方向编码 |
| R | 原K1/V1基码，沿冻结priority追加残差，完整费用不超过G8 | 同一笔预算买更细基码还是更多残差 |

A/B/C/D/G8的43槽是原low的K23/V20具体位置；原high采用它自己的26–44槽和位置，两者不能当作只差一个残差的单因素对照。R保护原43槽并追加原序列，不训练新的query选择器。

信息动作P现场重做原图prefill并构建原high；Z在原图之外增加相关ROI，Z-random采用同形状随机ROI，二者均建立完整原生多图前缀并真实压缩全部视觉KV。probe生成后回滚文本，再从原问题生成最终回答。没有拼接两个独立prefill的KV，也没有把新crop偷偷保留成FP16视觉缓存。

随后自主迭代了一个严格预算版本：减少全图tile，以原low的首回答前完整KV费用购买局部高精度。其相关crop与随机crop各48个回答，完成后因明显任务退化停止扩测。预算只约束首回答前的持久KV；probe、重新prefill、切换峰值、Host与全请求时间分开计入，不称为全流程资源中性。

## 中档R的数学与资源含义

以视觉token数N、实际残差槽数m表示，当前实现的完整视觉owner费用为：

`R = (3816 + 18m)N + 89737 bytes`

`G8 = 5486N + 155145 bytes`

因此R选择：

`m = min(224, floor((1670N + 65408)/(18N)))`

这是在已有固定次序下可负担的最长前缀，不是全局任务质量最优解。每多一槽花费18N bytes；R把均匀基础码扩容的字节改用于不均匀残差覆盖。新方法的固定4B格式字段和原所有元数据都已计入。

“约1.55bit”是典型值或逐域平均，**不是逐图统一1.55bit上限**。例如N=1792时m=94、实际1.55080bit；N=256时m=106、实际1.69490bit。报告须同时列逐题均值、元素加权值、最大值及覆盖分布，不借大图均值隐去小图开销。

## 辅助分析：平均预算下的端点混合

为判断中档收益是否只是花更多字节，另做一个事后辅助计算：让旧low/high以与图片、答案独立的概率混合，使期望视觉总字节与R相同。Info的high概率为0.51551、期望ANLS70.8871，R高0.6533pp（区间[−1.4329,+2.8185]）；Doc概率0.50751、期望90.8073，R高0.8250pp（区间[−0.5176,+2.2177]）。2000次来源bootstrap每次重新估计成本概率，不clip或丢弃抽样。

这是已闭合真实输出的期望质量派生分析，新增推理为0，不是重新运行的混合策略或预注册主判据。它匹配总体平均预算，单图可能选择约1.8bit的高档；不能当作与R相同的逐图上限。结果支持继续研究中档分配，但尚未确认优于端点平均预算凸包。

## 当前可支持的解释

更大码本、更小逐元素误差、更多局部采样都不是单调的任务收益。先导结果显示，细粒度残差覆盖值得晋级500；它并没有证明视觉KV容量已经到头，也没有证明所有模型都偏好同一种K/V分配。

相关ROI比随机ROI好，支持定位信号有用；只要它没有超过不裁图的原基线，就不能称作完整方法提升。严格预算裁图同时改变了全图密度、多图模板和精度，明显退化与全局信息损失的解释相容，尚不能把损失单独归给某一项。下一步可探索保留已有高密度前缀中的全局语义再补局部证据，但当前尚未实现、未验证。

原型时间包含审计与逐对象检查，按实际encode、wall、TTFT和allocator peak报告；未测HBM读带宽，也不把压缩字节自动换算为加速。

## 下一步优先测试的两个假说

**第一优先：扩大按头表示自由度，并直接对照完整学生后缀目标。** 112个KV单元各存一份G4_16书，共14,336B，比现有共享128B增加14,208B。N1792时约增加0.00221bit/原视觉元素；在共同G8费用上限内可消耗R尚未花掉的余量、保留94槽。N768或256时分别需少1或3槽，必须同时设置同donor删槽控制。它不是零成本，也不是已实现的新结果。

先把全局书原样复制到每个头，在同覆盖/同donor下验证恒等初始化的真实packed读出；再用同校准数据、更新预算做global/head × MSE/完整suffix的2×2对照。固定原f0、V与残差位置，K base变化后真实重编码K残差。历史已有按头G4_256 decoder-only实验，这里待测的是G4_16真实重选索引与完整学生后缀目标的组合，不能把“按头”本身当新贡献。完整suffix目标仍需经过自由回答和冻结500检验，不能因loss下降宣布成功。它与Round9已失败的一般“少量头升K2、删除残差”交换不同，新增的是每个头的码字方向自由度；与继续复训全局64参数也不同。

**第二优先：先形成全密度上下文，再选择存哪些KV。** 一般而言，先做模型上下文化再选状态，与先删图像信息再重新prefill不交换：`P_S F(X)`通常不同于`F(P_S X)`。本轮失败预算裁图属于先修改输入再prefill这一类，还改变了ROI与多图模板，并非这个表达式的严格单因素消融；保留原全密度形成的thumbnail及部分tile状态，可能在减少存储行数时保留更多全局语义。这是一条尚未验证的不同动作。

例如原N1792下，保留1536行并采用A的成本算术约9,894,409B，不高于R的9,960,073B；该数字还需要新稀疏实现的真实owner验收，不能当已经跑出的收益。首批应比较完整R、上下文化后保留状态、同形状随机保留，以及同保留数量的低密度重新prefill。保留原绝对位置、原问题模板与完整生成流程；删掉的视觉行必须实际消失，不能被归为FP16文本或藏进临时常驻状态。它也不是拼接两个独立KV。

这两条都先以同题任务收益和实际费用判断，再决定是否值得进入下一轮500；不增加本轮冻结候选，也不要求先跑全5000。
