# C2冻结case的数值闭环

**支持将C2_fp32_bias纳入后续固定pilot。** 新CUDA单层源操作重放与生产输出、旧冻结输出均位级一致；23项CPU前向误差检查全部通过。原待验证记录与FP16溢出失败保留，算法、clip、校准和原FP64终端阈值均未修改。支持状态见`audit/calibquant_fp32_bias_C2_support_v2.json`。

这次查清了最大差0.015625的具体来源，而不是用“小global L2”替它开脱。在同一head/query/channel，两组实际Half概率只差很小；精确加权码和却跨过了Half舍入格的中点：

|阶段|生产源路径|FP64 instrument路径|差值|
|---|---:|---:|---:|
|各自p下的精确加权码|1.5024420619|1.5024411082|9.537e-7|
|Half存档加权码|1.5029296875|1.5019531250|0.0009765625|
|乘scale=12.3515625后存Half|18.5625|18.546875|0.015625|
|待减的scale×zero×sum(p)|18.3125|18.3125|0|
|视觉输出Half|0.250000|0.234375|0.015625|
|加同一text项后最终Half|0.2526855469|0.2370605469|0.015625|

两精确加权码分别在中点`1.50244140625`上方6.557e-7和下方2.980e-7。两边都是正确的Half舍入；对于**同一实际p**，原WV kernel与FP64-rounded加权码仍完全相同。差异来自不同p跨舍入边界，再经过scale和仿射抵消。它不是WV kernel凭空产生了117个输出ULP。

整个capture的Half p最大L1差3.338e-6，`sum|delta_p|*|v|`最大逐通道界4.881e-5。最大输出差位置的该项仅3.278e-7；两路径已逐算子核验的舍入预算分别为0.01913和0.02269，完整界0.04182覆盖观测0.015625。全部78,848个输出坐标均满足前向界，最大观测/界比例0.522。每一归约先检查源FP32累积与Half store预算，仿射和最后相加再按Half舍入单独计账，没有假定CUDA expf是精确指数。

这里验证的是source0/layer26这一冻结q/owner与当前源程序的数值行为，不能推出所有输入或不同CUDA库都通过，也不产生新的任务质量得分。先前两图真实28层suffix/freegen有限证据，加上此次源程序和误差闭环，足以支持继续单题→固定128源→500源实测；后续所有nonfinite、zero-range或owner失败照常保留，不通过clamp或nan替换补格。

原论文推理默认BF16，本矩阵模型与text KV为FP16，方法始终标为显式FP32 bias归约视觉端口。它不是未经说明的原论文全系统复现。C2采用源合法bits2和K/V clip=1，不能用C1的bits1/不同clip及较低试评分替代这个更强对照。

`results/analysis/C2_roundoff_closure_v2/`保存可浏览的源重放、23项检查和逐阶段trace；它们已通过独立远端SHA复核。完整概率/算子pt留在8TB数据盘，未下载或公开上传。
