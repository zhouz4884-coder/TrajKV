# 固定原生q的视觉子集误差：四源五层CPU控制

数学note复核无代数错误。`beta+eta`、分区函数、输出分解、pruning的`log pi(S)`及TV紧界`tanh(R/4)`都成立，TV采用半L1定义；空保留集合等边界需按极限解释。12组有限分布和两点紧界CPU检查保存在`audit/partial_scope_math_review_v1.json`。

使用此前真实3090保存的4源×5层原生q/K/V，固定同一q和原始K/V，在CPU按冻结源码构造MSE Hmix12、Hmix23和single-Gaussian IP Hmix34，共60个算子控制。codebook、K-derived分组、norm dtype、旋转种子、单QJL因子及V默认MSE读法不变。文本未来位置按每个query屏蔽。没有读取GT、加载模型权重、运行GPU、改参数或产生新端到端分数；CPU重新编码不宣称与GPU每个边界索引位级相同。PT未下载。

这里beta/eta按该次source reader分数误差计算；由重构K均值投影得到的beta_K及FP32算术残差另列。统计轴是保存文件内的全部问题suffix query与head，包含问题状态形成中的早时刻，并非只取最终预测答案的那一个query。四源范围不是置信区间，head-query平均也不能代入非线性sigmoid公式。当平均视觉总量看似接近native时，不同head/query的正负偏移仍可相互抵消平均值，同时造成很大的输出误差。

最清楚的局限出现在边层。L0的MSE12/23有很大均值偏移；IP34的均值偏移减小，但其exact `log E_pi exp(eta)`平均为9.86–14.82，使视觉总量显著升高，条件路由TV为0.751–0.834，top1仅3.0%–22.0%一致。L27的IP34条件TV更低（0.320–0.328），仍有很大的mass和输出误差。因此全向量MSE、平均mass或单独top1都不足以解释最终读出。中层7/14/21的IP控制则明显温和，不能把边层现象推广到全部层。

eta的均匀均值为零，不代表pi加权均值为零；本次部分MSE中层的exact logmoment为负。不能只凭“方差”断言视觉权重一定提高。输出中的mass项、routing项与value项均已分列，它们的向量会抵消，范数不应简单相加当作实际损失。

single Gaussian路径没有显示漏/重复校正证据：原存档IP residual norm与原K减MSE重构后的FP32重算完全相同；单投影dot恒等残差最大7.28e-12，公开FP32 decode对其精确向量形式relative L2约4.4e-8–5.8e-8。L0 residual平均范数42.65–46.44，L27为30.33–39.31，中层仅约2.37–2.86。在这四源上，IP的全向量K误差低于较低bit的MSE12/23，仍未保证边层对比度和分区函数稳定。不同变体位宽并不相同，不能把跨变体差全部因果归于QJL。

全部60个固定q的logZ恒等残差≤5.69e-13、输出分解残差≤3.81e-15；source CPU reader对该固定source分数、精确text算术分解的输出差relative L2为1.72e-4–2.14e-4。实际分数与重构点积的FP32数值残差另存，不能混入beta机制解释。它们支持本次分解的一致性，不是任务质量、GPU性能或可部署在线估计器证明。

完整小JSON/CSV位于E镜像`results/analysis/partial_scope_native_cpu_all4_v1/`；D的同名目录保存可浏览的60行摘要、15组层范围和源码/取回指纹。原始PT继续只留8TB。结论限于这些固定原生查询；真实压缩前向的后续q漂移、执行边界、其他模型和正式数据集得分仍须分别测量。本轮没有修改任何方法，也未触碰GPU任务或原生F全量收数器。
