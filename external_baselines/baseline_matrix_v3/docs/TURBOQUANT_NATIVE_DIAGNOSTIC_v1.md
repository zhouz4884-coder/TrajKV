# 原生q/K/V诊断：当前uniform TurboQuant视觉端口在哪失真

本次是真实3090、M1、预定Text/Info各前2题、每题6臂的诊断，24个分支均完成。原生F suffix logits与各自native参考逐元素相同；每臂独立重算问题suffix和首token。新增R128以及V4后，输出仍出现碎裂和重复，尚未恢复F的短答案形式。这4题没有在诊断中读取参考答案或生成新的任务得分，不代表数据集或所有模型的普遍结论。

**目前最有力的解释是：K的量化误差淹没了用于区分视觉token的微小对比，同时改变了视觉缓存与精确text缓存之间的竞争。** 大型packed-reader错误不再像主要原因：同一个native q/K/V上的packed与独立dense解码attention相对L2约1.8e-4–2.1e-4；T0的packed和dense自由生成在4题上前16个token完全一致，且都碎裂。T128只有2/4题的两种reader生成ID完全一致，说明小浮点差仍可使greedy分叉，不能据此声称两个后端位级等价。

表是4个来源的范围，使用T0/packed的同native-q单层干预。均值能量是`N*sum_h||mean_i K_hi||²/sum_hi||K_hi||²`，不是声称每个head都有同样比例。L0的K cosine仍约0.918，但跨位置居中logit相关仅0.257–0.287，说明好的全向量cosine没有保证正确的细小路由对比。L0平均视觉注意质量从0.208–0.255上升至0.774–0.939；在这个固定q的单层干预里，K-only误差远大于V-only误差。整模型分支后续q还会改变，因此单层结果不等于最终答案损失的加法分解。

可用的数学分解是`K_i = mu + delta_i`、`z_i = q·mu + q·delta_i`。区分视觉位置依赖`q·delta_i`；按整个`||K_i||`标定的量化误差可能远大于这部分信号。即使误差主要是视觉段共同偏移，它也只作用于视觉keys，不能使用“softmax对全局常数平移不变”把它消去：精确text logits没有同步平移。若还有token间不一致的量化误差，视觉内部排序也会改变。本次居中logit噪声与视觉/text质量变化同时出现，支持继续检查这个双重失真假设，但没有证明是哪一个结构单独决定了全部答案。

此前CPU代理只用了Calib2重建的layer26视觉K/V及C2分支q，其均值份额约37.5%；它不能代表L0或L27。原生多层新结果修正了这个观察范围，而不是把代理结果改写为原生实测。

选中0xSero实现的uniform K3/V2（及K3/V4）和R128静态prefill端口仍不是TurboQuant论文的mixed outlier/nonoutlier配置，也不是Google官方VLM复现。本次不能用于宣称原论文方法失败或TrajKV已领先。下一步基线工作应优先审查另一公开实现及论文配置覆盖；若继续研究共享均值、慢RoPE通道或量化残差分布，那些是待验证机制。额外中心化、只保护某些层等改动应另立诊断/方法身份，不能混进原外部方法结果。
