# Round9 已闭合开发阶段：18次真实运行，704个回答事件

本阶段完成 InternVL3-8B、固定cap8和R7已校准V0下的两轮K方法探索。所有新增模型任务在两张RTX3090真实前向、实际packed reader和自由生成上运行；数据、模型与新缓存均在项目数据盘。704是回答事件数，不是704个独立来源：参考256、第一轮K码本128、MSE后半批64、归因诊断128、基码—残差交换128。正式四域500题属于另一个已发布的R7阶段，不与本开发分数混算。

## 本轮新增方法与归因

基码—残差交换固定全部V字段、20个V残差和K原head factors。一个层四个KV头从G4_16升为G4_256，基础索引增加64N字节；四个K符号残差释放72N字节。全局lookup从I32改I8释放1344字节，实际新增高书2048字节、格式表28字节及donor描述12字节。

因此Exchange完整owner相对原R7低档为744−8N字节；Drop4为−72N−1304字节。两者都不超过原低档预算，但实际花费不相等。Exchange比Drop4多64N＋2048字节。

原32源压缩学生query校准、完整视觉＋文本路由KL选择了层14和四个K donor。局部KL从0.1385427977到0.1333908206，四删完整重放与可分预测残差5.55e−17。N=256/1792的真实GPU检查覆盖3种模式×28层，共168个reader及字段对照，输出bitwise一致，物理字节账一致。所选层14原唯一K残差恰被删除，因此本profile的“升级层保留K残差重编码”分支为空；不冒称这个非空分支已在该GPU检查中覆盖。

当前小集里，Drop4平均完整bit为Text1.275633、Info1.278516，两组32的最大值均1.292729；Exchange为1.293839、1.296788，最大1.311331。Drop4这两组32请求均≤1.3bit，但不能外推正式500，尤其小N请求。Exchange是R7低档实际预算上限下的比较，不是严格1.3bit全请求方法。

编码中位时间约5.7–5.8秒，原R7约5.5–5.6秒；质量run混有答案长度、新shape编译与并行背景，当前没有受控提速证据。

## 数值修复与证据边界

新calv1在当前Torch2.4.1/cu121/3090环境的F64融合log_softmax宽度797上中断。独立随机输入和同一真实失败来源都复现了归一化失真。calv2改用显式max-shift/exp/sum/log，真实同源CPU/GPU log概率差约1.78e−15，原KL/链式分解阈值未放宽。旧失败run和源码保留；此故障不是新方法任务失败，也不改变此前任务评分。

源码、参数、输入来源、实际job/launch/snapshot、原始预测、评分和完整owner分别绑定。私有采样PT、W_O和模型权重不公开；其哈希仅由实际producer记录，不冒称归档包含了这些张量或可在无模型数据下重跑采样。公开归档支持从原始文本回答复算分数和检查已声明的来源闭包。

## 当前判断与下一步

本阶段没有稳定的新K赢家。Text的结果反而支持“某些残差可损害答案”这条线索；Info对基础索引升级有小信号。两条都需要新来源复测。

两个版本已经冻结，后续用另留的Text/Info各32来源，在同题FP16、R7、Drop4、Exchange下复测；原版本不根据这些结果重训。这是新的来源复测与候选比较，不冒称预注册统计确认。并行实现的三层/11donor方案只由已有校准成本的动态规划选择，不用新来源任务结果挑profile；它的局部预测也必须经过新packed格式与真实答案验证。

这一公开增量只关闭已完成18次运行及其支持证据，不声称整个Round9目标、后续复测、多模型适配或全部外部SOTA矩阵已完成。R7四域500完整结果已在既有release独立发布。
